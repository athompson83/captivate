## The model gateway

- [x] Text and image generation each reach a provider through a resolved gateway rather than a hardwired one: Anthropic or OpenRouter for text, OpenAI or OpenRouter for images. `CAPTIVATE_AI_PROVIDER` and `CAPTIVATE_IMAGE_PROVIDER` name a gateway outright for the deliberate switch; with neither set the answer comes from which keys are present, so the ordinary case is adding a key rather than keeping two variables in step. The incumbent wins a tie — Anthropic for text, OpenAI for images — because adding an OpenRouter key beside a working one must not silently move a running deployment onto a different gateway.
- [x] The retry policy, error text and schema validation are shared across providers; only the `Conversation` — how to ask, and how to put a rejected answer back — differs, which is the half that genuinely does.
- [x] `0027` prices six OpenRouter models; `generation-cost` reads every migration and asserts both provider defaults are priced, since a model with no rate row settles at zero cost silently.
- [x] **A ledger row names the gateway that was paid, and cannot be made to lie about it.** `0028` added `ai_generations.provider`, first as a caller-supplied argument to both settlement functions — the same trust boundary this file already accepts for `model` and token counts (see `0020_ledger_integrity.sql`), except that lying about `model` prices a row near zero at the forger's own expense, and lying about `provider` alone cost the forger nothing while corrupting the one column added specifically so a human could read off which balance was charged. `athompson83` raised it on PR #61 the same day Codex flagged it independently; `0029_gateway_from_model.sql` removed `p_provider` as a parameter entirely and derives it inside each function from the model id it is settling — an unprefixed id is a direct call, a `vendor/`-prefixed one is OpenRouter, the convention `DEFAULT_MODEL`/`DEFAULT_IMAGE_MODEL` already use — so a caller can no longer name a gateway disconnected from the model it supplied. No new credential was introduced; one previously-independent lie was retired. Applied to `qnbwyymwhvqprjtyfdmb` on 2026-09-03 and read back: both functions carry their original, pre-`0028` argument count again, `authenticated` may execute them and `anon` may not. The RLS suite asserts both derivation branches (direct and OpenRouter-prefixed) for text and image settlement alike.
- [ ] **No generation has ever run through OpenRouter, and production does not need one.** Every settled text row on production names `claude-sonnet-5` through Anthropic directly, and the one image row names `gpt-image-2` through OpenAI: the resolver picks the incumbent on both sides, as designed. The OpenRouter client is still a design for being wrong safely rather than evidence of being right — the first real generation through it remains the test — but nothing in production waits on it, and its exhausted account balance ($35.06 of $35.00) affects nothing users do.

## Generation reliability

- [x] **`create-from-map`'s client-visible failure message is honest.** PRs #63 and #64 fixed the symptom a user actually saw: a toast claiming "Your work is unaffected" after a connection dropped mid-generation, when the route had already written the presentation's structure. Fixed for both ways the connection can drop — `fetch` itself rejecting, and a resolved OK response whose body fails to parse. See BETA-006 above for what neither PR touched.
- **Fluid Compute is `DEFERRED`, not the fix.** Raising `maxDuration` beyond 300s would reduce how often `create-from-map` outlasts the connection, but a request could still fail from a dropped connection, a runtime kill, a provider interruption, browser abandonment, or one scene's own failure — none of which a longer ceiling closes. It stays a separate performance/operating-cost decision, to be evaluated on its own terms later, not purchased to patch this correctness gap.

- [x] **A generation that is walked away from finishes, and says so.** Vercel's request
      cancellation is opt-in and this project does not enable it, so the function completes
      whether or not a phone stayed awake — what did not survive was the author's ability to
      find out. Two identical decks a minute apart in production, each sixteen moments and
      sixteen placeholder scenes, is what "I could not tell what happened, so I pressed it
      again" looks like in a table. `presentations.generation_status` (`0032`) records
      `generating` before the model is called and `ready` / `partial` / `failed` after; a claim
      older than the route could still be running reads as stalled rather than as a spinner
      that never resolves.
- [x] **The scenes are written by the server, not by a loop in the page.** `scenes-from-map`
      used to hand every scene back for the browser to save one at a time, which put a
      five-minute job behind a lock screen. `planSceneWrites` decides the whole write before
      anything is written, and the route executes it.
- [x] **Generating never grows the deck.** Two separate defects made it do exactly that, and
      both are fixed: a map derived from a deck's own scenes names each moment by the scene's
      id, and a template's declared shape wrote moments that named nothing at all. A template
      deck's eleven scenes became nineteen in CI, twice, which is how each was found.
      `0033` repairs the decks created before the fix.
