## Required User Actions

- Set the Stripe account's public business name to **Axtevi**. It is what appears on card statements, receipts and the Billing Portal.
- Set `PEXELS_API_KEY` in Vercel for stock photography, if it is not already set — nothing in this session can read it. The image key is no longer an action: a generation completed in production on 2026-09-02, so one of `OPENAI_API_KEY` / `OPENROUTER_API_KEY` is present and working. Without a photography key, a generated deck's only pictures are the staged drawings the text model produces and whatever the author generates by hand — measured on a real deck before imagery worked: two drawings across twenty-one scenes.
- Supply the brand assets as files in the repository (`public/`), rather than as images in conversation. The wordmark component is in place and the palette is the mark's, but the tile is still a placeholder glyph and the favicon and share card are unchanged.
- Confirm `STRIPE_WEBHOOK_SECRET` is the signing secret of the endpoint matching the mode of `STRIPE_SECRET_KEY`. Test and live endpoints have different secrets, and a mismatch fails every delivery while everything else looks correct.
- Delete the two disposable `webhook-probe@example.com` customers left by the end-to-end proof (tagged `delete_me`); the MCP in use cannot delete customers.

Before public launch the owner still needs to: enable leaked-password protection in the Supabase dashboard (Auth → Policies — dashboard-only, no management token available to the agent); set `NEXT_PUBLIC_SUPPORT_EMAIL` in Vercel so the legal pages can name a real address; decide email policy and provider; review the privacy and terms wording, whose facts are code-derived but which has had no legal review; and accept the release as shipped/live.

One of those decisions is not a preference but a gap. `docs/SECURITY.md` records that there is **no account-deletion flow**: the cascading deletes exist in the database, and nothing in the UI reaches them, so removing an account is done by hand. The privacy page says so plainly rather than implying a button exists. Whether that is acceptable at launch or blocks it is the owner's call and has **not been made**; it is recorded here rather than left implicit, because a gap nobody decided about is indistinguishable from one nobody noticed.

None of these blocks current engineering.

## Pricing and the spend boundary

- [x] Allowances set at 10 / 25 / 60 presentations per rolling 30 days, with every other pool derived from what one presentation consumes.
- [x] The reservation reads its own ceilings and its own plan; a caller can no longer name either. Both the rolling allowance and the hourly burst ceiling are enforced inside one lock, and each is raced by `supabase/tests/reservation_race.sh`.
- [x] The tier a subscription grants is stored when the webhook writes it, so rotating a price cannot downgrade a paying customer.
- [x] Every settled text generation records what it cost, priced from effective-dated model rates.
- [x] Top-ups are purchasable, and a credit buys a whole presentation rather than a deck counter — asserted end to end.
- [x] Annual billing withdrawn: no code path can open an annual checkout, and the annual price ids are recognised only.
- [x] **Generated imagery works in production.** Read back from `ai_generations` on 2026-09-02: one `kind = 'image'` row, `status = 'succeeded'`, model `gpt-image-2`, 41.7 s, $0.05, created 15:39 UTC on a real presentation by an account holding a `pro` grant — the first image generation the deployment has ever completed. The model id carries no `openai/` prefix, which is how the OpenAI gateway's default is named — consistent with OpenAI having served it, and not proof: the ledger persists the model string and not the gateway, and a `CAPTIVATE_IMAGE_MODEL` override would record the same value through OpenRouter. ## The model gateway

- [x] Text and image generation each reach a provider through a resolved gateway rather than a hardwired one: Anthropic or OpenRouter for text, OpenAI or OpenRouter for images. `CAPTIVATE_AI_PROVIDER` and `CAPTIVATE_IMAGE_PROVIDER` name a gateway outright for the deliberate switch; with neither set the answer comes from which keys are present, so the ordinary case is adding a key rather than keeping two variables in step. The incumbent wins a tie — Anthropic for text, OpenAI for images — because adding an OpenRouter key beside a working one must not silently move a running deployment onto a different gateway.
- [x] The retry policy, error text and schema validation are shared across providers; only the `Conversation` — how to ask, and how to put a rejected answer back — differs, which is the half that genuinely does.
- [x] `0027` prices six OpenRouter models; `generation-cost` reads every migration and asserts both provider defaults are priced, since a model with no rate row settles at zero cost silently.
- [x] **A ledger row names the gateway that was paid.** `0028` adds `ai_generations.provider`, constrained to `anthropic`, `openai` or `openrouter`, and both settlement functions take it as a defaulted final argument — so the build that was running when the migration was applied kept settling, with the gateway unrecorded, until it was rebuilt. Text settlement passes the resolved `AI_PROVIDER`; image settlement passes `IMAGE_PROVIDER`. The row that motivated it (the first production image generation, `gpt-image-2` with no prefix) could only be read as "consistent with OpenAI", because `CAPTIVATE_IMAGE_MODEL` overrides the default independently of the provider and the same string records through either gateway. Rows settled before `0028` keep a null rather than a backfill from the current environment. Read back from production on 2026-09-02: both new signatures present, the old ones gone, `authenticated` may execute and `anon` may not. The RLS suite asserts that an unknown gateway is refused and leaves the row pending, and that a known one is recorded, for text and image rows alike.
- [ ] **No generation has ever run through OpenRouter.** The request and response shapes come from OpenRouter's reference and were checked against its live `/api/v1/models` and `/api/v1/images/models` endpoints — so the catalogue was read, but no completion and no image was ever asked for. Every response is Zod-validated, so a wrong shape degrades to a sentence rather than a crash. That is a design for being wrong safely, not evidence of being right. The first real generation is the test.
